Known limitations

This list is deliberately explicit.

Not available yet

  • shells, plates and beams: Elmer has ShellSolver and the Smitc plate solver, but Solid Mechanics in Studio is continuum only;

  • 3D magnetic fields (A–V formulation);

  • turbulence;

  • contact, nonlinear materials and prestressed (harmonic perturbation) structural analysis;

  • damped (complex) eigenfrequencies: the eigenfrequency study ignores Damping;

  • acoustic boundary elements (BEM) and perfectly matched layers. Open acoustic domains use Spherical Wave Radiation, and the field beyond the mesh comes from the Exterior Field Calculation;

  • exterior field calculation in 2D planar models (it would need Hankel functions);

  • result filters, dataset joins, and Combined/Array datasets;

  • adaptive mesh refinement;

  • LiveLink-style CAD synchronisation;

  • the Application Builder;

  • reading or writing COMSOL .mph files.

Partly supported

  • Boundary layers are meshed in 2D and 2D axisymmetric models only (gmsh’s boundary-layer field is two-dimensional); in 3D the Boundary Layers node is not offered, and Studio’s single node takes the boundaries directly (COMSOL nests them in a Boundary Layer Properties subnode).

  • Solid Mechanics in a Frequency Domain study: stresses are not computed (Elmer gives those of the real part only), loads have zero phase, and a Roller or Symmetry condition must lie on a boundary perpendicular to a coordinate axis (Elmer’s harmonic solve does not rotate a normal-tangential constraint back, so other boundaries are refused). Eigenfrequency studies constrain such boundaries the same way; on an inclined or curved one they keep Elmer’s normal-tangential form, with a warning.

  • Damping is Rayleigh damping (mass and stiffness proportional), as in COMSOL’s Damping subnode; loss-factor damping is not offered. A Time Dependent structural study starts at rest (zero initial velocity).

  • Probes are evaluated from the saved output steps (every output time, frequency or parameter value), not at the solver’s internal steps; while a study runs the Probe Table follows the outputs written so far (time-dependent studies).

  • Animations are written as an animated GIF or a PNG image sequence; there is no AVI/WebM output and no player inside the Graphics window.

  • Clicking a result plot to read its value (Evaluation 2D / Evaluation 3D) works in 2D and 3D plot groups only. 1D and polar graphs are matplotlib figures: for a value at a point there, use a Point Evaluation or a Point Graph. A click reports the plots of the group that use the clicked plot’s dataset; plots on another dataset are left out of that row.

  • Library materials have constant properties at 20 °C, unless you enter an expression.

  • The physics-controlled mesh refines automatically only for laminar flow and acoustics.

  • With an incident plane wave the acoustic solution is the total field. The exterior field is then most accurate when integrated over the scatterer’s surface.

  • Coupling operators work in results, not inside the equations.

  • In the electrochemistry interfaces, there is no electrode (solid-phase) domain, total-power electrode condition, or double-layer capacitance. A total current on an Electrode Surface works in Stationary studies, for one electrode per component: the study repeats the solve, adjusting the electrode potential, until the current matches (a few solves).

ElmerGrid mesher

The ElmerGrid mesher (Mesh) covers only part of what ElmerGrid can do:

  • Only layouts of axis-aligned rectangles and blocks. ElmerGrid’s geometry mappings (curved lines, sine waves, circles), revolved meshes, polar shells and 1D meshes are not used, so curved or rotated geometry needs gmsh.

  • Every subcell gets equal elements. ElmerGrid’s element ratios and densities are not exposed, and Distribution nodes and local Size nodes are refused.

  • In 3D, ElmerGrid makes at least two element layers in z in every layer of blocks.

  • Quadratic prisms are not available: ElmerGrid extrudes only linear triangles.

  • ElmerGrid’s mesh conversion (from other formats) and its clean-up options such as -autoclean are not offered: they renumber bodies and boundaries, and Studio’s selections depend on the geometry’s numbers.

  • A boundary that lies inside a single domain (an embedded line or face) has no ElmerGrid elements, so the mesh is refused.

  • Remeshing in a deforming-domain study uses gmsh. Messages says so when it replaces an ElmerGrid mesh.

Partitioning for MPI runs is done by ElmerGrid (Metis) for both meshers, as before.

Desktop

  • The desktop has one light theme. The Graphics window has light, white and dark themes, with a separate theme for exported images.

  • F1 opens the help in the web browser. There is no Help window inside the desktop.

  • Recovery keeps the unsaved model and reuses the interrupted session’s solutions, but cannot continue a solve from where it stopped (COMSOL’s Continue).

  • The mouse wheel zooms. Hidden entities are reached with Up/Down or +/- (the wheel does not step through them).

  • A font size change takes effect at the next start.

Approximations

  • Integrals over quadratic elements use linearized cells (about 0.1 % on smooth fields). Boundary fluxes from reaction loads, such as electrode currents and heat flows, are exact.

  • Units are checked and reported, but a value of the wrong unit is still used (its SI number), as in COMSOL.

  • A component uses another component’s results only through coupling operators (scalars), one way, evaluated once per study step.

  • Identity pairs give continuity for scalar fields (heat transfer, electrostatics, electric currents, coefficient-form PDE); solid mechanics, flow and transport do not use them yet.

Parallel computing

MPI runs need an MPI-enabled Elmer. The Windows -nompi builds of Elmer run serially.

  • On more than one process, UMFPACK direct solves become BiCGStab with ILU(0), and the Newton line search is off. An eigenfrequency study keeps its direct solver, so in parallel it needs an Elmer with MUMPS.

  • Parallel runs of the tutorial cell were checked against the serial result with an MPI Elmer on Windows (MS-MPI) and Linux (Open MPI). On macOS only the search for mpiexec is tested; no macOS MPI run has been made.

OpenFOAM backend

The OpenFOAM backend (see OpenFOAM backend) is deliberately narrow:

  • Laminar Flow and Heat Transfer in Solids only, one physics per study step, stationary or time dependent;

  • blockMesh only: unions of axis-aligned rectangles (2D) or blocks (3D). No gmshToFoam or snappyHexMesh for other shapes, and no 2D axisymmetric wedge;

  • no turbulence, multiphase, conjugate heat transfer between regions, or parallel decomposition;

  • one constant density and viscosity (or k, ρ, Cp) for all domains;

  • the outlet sets p = p0 with a zero normal velocity gradient. It equals Studio’s traction outlet only where the flow leaves parallel;

  • no conductive heat flux (ht.tflux) in the results;

  • equally spaced output times with a fixed time step;

  • verified with OpenFOAM v2606 under WSL. The Windows (msys) launcher for the ESI v2106 tree and a native Linux install are implemented but not verified.
