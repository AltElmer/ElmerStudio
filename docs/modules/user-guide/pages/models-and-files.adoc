= Models, files and the Model Builder
:description: Creating, opening and saving models; components; working with nodes; undo; Application Libraries.

== Starting a model

menu:File[New] (kbd:[Ctrl+N]) opens the *New* window, with three ways to start:

Model Wizard:: Pick a space dimension (*3D*, *2D Axisymmetric*, *2D*), one or more physics interfaces, and a study type. The wizard creates the component, the physics with their default features, an empty geometry, and the study. Several physics can be added in one go. Some entries, such as *Joule Heating* and *Thermal Stress*, add two interfaces and their coupling.
Blank Model:: An empty tree with *Global Definitions* and *Results*. Add a component with menu:Home[Add Component], physics with menu:Home[Add Physics], and a study with menu:Home[Add Study].
Application Libraries:: Ready-made, solvable models. See xref:tutorials:application-library.adoc[Application Library examples].

== Components and space dimensions

A model has one *Component* with a fixed space dimension:

[cols="1,3",options="header"]
|===
|Space dimension |Use it for
|3D |General solids and fields.
|2D |Planar problems: cross-sections of long objects (plane strain), thin plates (plane stress), planar fields and flows.
|2D Axisymmetric |Bodies of revolution about the z axis, with coordinates r (x) and z (y). Integrals over the model are taken in the revolved geometry (×2πr) unless you turn that off.
|===

== Saving and opening

* menu:File[Save] (kbd:[Ctrl+S]) and menu:File[Save As...] (kbd:[Ctrl+Shift+S]) write an `.esm` file. It is a zip archive with the model (as JSON) and the computed solutions, so plots and tables come back when you open it. The file is written to a temporary name and renamed when it is complete. If saving fails, the model keeps its previous file name.
* menu:File[Open...] (kbd:[Ctrl+O]) and menu:File[Recent] reopen models. You can also pass a file on the command line: `elmerstudio model.esm`.
* When you open another model or close the window, Elmer Studio asks about unsaved changes. It also removes the temporary working folder of the model you leave. The title bar's `*` follows undo: undoing back to the saved state clears it, and undoing past it sets it.

[#file-format]
=== What the file holds

[cols="1,3",options="header"]
|===
|Entry |Content
|`model.json` |The model tree: every node and setting.
|`work/<study>/<solution>/` |Each computed solution: `meta.json` (status, solver diagnostics, the parameter values it was computed with), `mesh.npz`, the result files, `model.json` (the model as it was solved), `solver.log`, and for deforming geometries the frame coordinates (`frames.npz`) and remeshed topologies (`mesh_<k>.npz`).
|`assets/` |Copies of external files the model reads, such as imported CAD geometry.
|`manifest.json` |The size and SHA-256 of every stored file, and whether solutions were included.
|===

On opening, Elmer Studio checks every stored file against the manifest. Missing or damaged files are listed in a warning, and the affected solutions are not shown until you compute again. A file saved without solutions opens without that warning. If an imported CAD file is no longer at its original path, the model uses the packaged copy. A file whose entries point outside its own folder (such as `../`) is refused.

== Working with nodes

Everything in the model is a node of the Model Builder tree:

* *Add* nodes from the ribbon or by right-clicking the parent node. New nodes are labelled with a number (*Temperature 1*, *Temperature 2*) and get a short name (`+temp1+`) used in expressions and variables.
* *Rename* with kbd:[F2]; *Duplicate* with kbd:[Ctrl+Shift+D]; *Delete* with kbd:[Delete].
* *Disable* (kbd:[F3]) and *Enable* (kbd:[F4]) a node to leave it out of the model without losing its settings.
* *Reorder* with kbd:[Ctrl+Up] and kbd:[Ctrl+Down]. Order matters in the geometry sequence (features build top to bottom) and among physics features (later wins).
* *Undo* (kbd:[Ctrl+Z]) and *Redo* (kbd:[Ctrl+Y] or kbd:[Ctrl+Shift+Z]) cover every change to the tree and to settings.

After a change, the geometry and mesh are rebuilt the next time they are needed (for example when you compute).

[#recovery]
== Recovery

While a model has unsaved changes, Elmer Studio writes a recovery checkpoint every minute and before every computation. Set the interval in menu:File[Preferences...]. The checkpoint is removed when you save, open another model or close normally. If Elmer Studio ends any other way (a crash, a power cut, a killed process), the next start opens the *Recovery Files* window, as COMSOL does. It lists each unsaved model with its time and file name, and names the computation that was running. menu:File[Recovery Files...] opens the same window later.

*Open* opens the model as unsaved, under its file name; the file itself still holds the last saved version, so save to keep the recovered one. The solutions of the interrupted session are reused when they are still there, but a computation that was running may have left an incomplete solution, so compute it again. *Delete* discards a checkpoint and *Later* keeps it for the next start.

Checkpoints are stored per user (`%LOCALAPPDATA%\ElmerStudio\recovery` on Windows, `~/Library/Application Support/ElmerStudio/recovery` on macOS, `~/.local/state/ElmerStudio/recovery` on Linux).

== Exporting

[cols="1,3",options="header"]
|===
|Command |Result
|menu:File[Export Elmer Case] |A folder with the Elmer mesh and `case.sif`, runnable with `ElmerSolver case.sif` on any machine with Elmer.
|menu:Results[Image] (Export) |A PNG of a plot group, at the size you choose.
|menu:Results[Data] (Export) |Coordinates and one or more expressions at every mesh node (last solution), as CSV.
|menu:Results[VTK Unstructured Grid] (Export) |The solution (`.vtu`) for ParaView or other VTK tools.
|menu:Results[Report] |An HTML report: the parameters with their SI values, the component's nodes, and a picture of each 3D/2D plot group.
|===

See xref:results.adoc#export[Results › Export].
