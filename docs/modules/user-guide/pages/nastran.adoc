= NASTRAN-95 backend
:description: Solving Structural Mechanics and Heat Transfer with NASTRAN-95 instead of ElmerSolver, what is supported, what is refused and why.

A study can be solved by *NASTRAN-95* (finite elements, MSC/NASTRAN compatible input decks) instead of ElmerSolver. You build the model exactly as for Elmer: geometry, materials, physics features, mesh settings, study. Only the study's *Solver backend* setting changes. The results come back into the same Results machinery, with the same variable names and SI units as an Elmer solution, so plots, derived values, selections and export work unchanged.

NASTRAN-95 covers a well-defined subset. Anything it cannot represent faithfully is refused before anything runs, with a sentence saying why and what to use instead. Elmer Studio never falls back to Elmer silently.

== Choosing the backend

Select the study node and set *Solver backend* (section _Study Settings_) to *NASTRAN-95*. The default is *Elmer*, and models saved before this setting existed open with Elmer.

When the model cannot be solved by NASTRAN-95, *Compute* is unavailable and its tooltip says why ("Unavailable: ..."), and the study node carries an error mark with the same sentence. Reasons that need the geometry are reported when you click *Compute*, before anything runs.

NASTRAN-95 is found through:

* the *NASTRAN installation folder* in Preferences (Settings > NASTRAN installation folder), which must contain `nastran.exe` and an `rf/` directory;
* `NASTRAN_HOME` environment variable (Windows native folder);
* `NASTRAN_WSL_HOME` environment variable (WSL path to a verified build, e.g. `/home/<user>/NASTRAN-95`);
* standard locations on PATH and in common install folders;
* on Windows, a WSL build if no native one is found.

With the NASTRAN study selected, menu:Study[Show NASTRAN Input Files] lists the generated Bulk Data deck without running anything: the Executive Control deck, the Case Control deck, and the Bulk Data section with all GRID, MAT, element, SPC, and load cards.

== What is supported

[cols="1,3",options="header"]
|===
|Model |NASTRAN-95
|*Solid Mechanics*, linear statics |`SOL 1` (DISP), linear elastic, 2D plane stress and 3D
|*Solid Mechanics*, normal modes |`SOL 3` (DISP), real eigenvalues via GIV (2D) or INV (3D)
|*Solid Mechanics*, transient |`SOL 9` (DISP), not yet implemented
|*Heat Transfer in Solids*, steady conduction |`HEAT 1`, linear isotropic
|*Heat Transfer in Solids*, transient |`HEAT 9`, not yet implemented
|2D geometry |Plane stress: CTRIM6 (6-node quadratic triangle) for structural; CTRIA3 for thermal
|3D geometry |CTETRA (4-node linear tetra), CHEXA (8-node hexa), CPENTA (6-node wedge) from 10-node tet split
|Parametric sweeps |One NASTRAN run per parameter value
|===

=== Feature mapping

NASTRAN-95 uses free-field card format (comma-separated, no column alignment required). All values are in SI base units; the deck is self-consistent with the model's parameter definitions.

[cols="2,2,3",options="header"]
|===
|Studio feature |Structural |Thermal
|Material: Structural Steel (E, ν, ρ) |`MAT1, MID, E, , ν, ρ` |—
|Material: Thermal (k, ρ, C~p~) |— |`MAT4, MID, k, C~p~, ρ`
|2D element property (plane stress) |`PTRIM6, PID, MID, t` (6-node tri) |`PSHELL, PID, MID, t` (CTRIA3)
|3D element property |MID referenced directly on element card |MID referenced directly on element card
|Fixed constraint (3D solid) |`SPC1, SID, 123` (DOFs 1,2,3) + `PS=456` on GRID |—
|Fixed constraint (2D solid) |`SPC1, SID, 123456` (DOFs 1-6) + `PS=3456` on GRID |—
|Enforced displacement |`SPC, SID, G, C, D` per DOF |—
|Temperature boundary |— |`SPC, SID, G, 1, T`
|Nodal force |`FORCE, SID, G, 0, F, nx, ny, nz` |—
|Gravity |`GRAV, SID, 0, g, gx, gy, gz` |—
|===

=== Element and property cards

*Structural 2D (plane stress):*
- 6-node quadratic triangle (gmsh order: 3 corners + 3 mid-sides) → `CTRIM6` with `PTRIM6`
- Property: `PTRIM6, PID, MID, t, MID, 1.0, MID` (membrane, bending, shear)

*Structural 3D:*
- 10-node quadratic tet → split into 8 linear `CTETRA` (all 10 nodes kept, `GRID` cards for every node)
- 20-node quadratic hex → `CHEXA` (corners only)
- 15-node quadratic wedge → `CPENTA` (corners only)
- 3D solid elements reference `MID` directly; no `PSOLID` card
- `GRID` cards include `PS=456` to constrain rotational DOFs 4,5,6 (zero stiffness in CTETRA/CHEXA/CPENTA)

*Thermal 2D:*
- 6-node quadratic triangle → split into 4 linear `CTRIA3` with `PSHELL`
- Property: `PSHELL, PID, MID, t`

*Thermal 3D:*
- Same 3D elements as structural, reference `MID` directly
- No `PSOLID`; `CTETRA`/`CHEXA`/`CPENTA` use `MAT4` directly
- `GRID` cards without `PS` (no structural DOFs)

=== Normal modes (SOL 3)

The `EIGR` card requests the first N positive eigenvalues:
- 2D: `EIGR, SID, GIV, , , NEIG, NEIG` — Givens method with ND=NEIG prints first N roots
- 3D: `EIGR, SID, INV, 0.0, 1000.0, NEIG, NEIG` — Inverse power method, iterative, avoids Givens time estimate explosion
- `+EIG1, MASS` normalization for modal mass

The parser extracts from the `REAL EIGENVALUES` table: MODE, EXTRACTION ORDER, EIGENVALUE, RADIAN FREQUENCY, CYCLIC FREQUENCY (Hz), GENERALIZED MASS, GENERALIZED STIFFNESS. Only rows with `gen_mass ≈ 1.0` and `gen_stiff ≈ eigenvalue` are kept (padded zeros after extracted modes are discarded).

=== Mesh

The Studio mesh (Gmsh) provides quadratic elements (10-node tets, 6-node triangles). NASTRAN-95 accepts only linear elements, so the backend splits them:

- 10-node tet → 8 linear CTETRA (4 corner tets + 4 interior tets from mid-edge nodes)
- 6-node triangle → 4 linear CTRIA3 (structural: CTRIM6; thermal: CTRIA3)
- 20-node hex → linear CHEXA (corners only)
- 15-node wedge → linear CPENTA (corners only)

All mesh nodes are emitted as `GRID` cards (node ID = mesh index + 1). No renumbering or mid-side node dropping is done.

Cell counts come from the Mesh node's *element size* settings, same as for Elmer. The Mesh node's *Distribution* and *Size* children are respected.

=== Results

Each solution folder holds the NASTRAN case (`nastran/` with `case.inp`, `case.out`), the logs, and the same files as an Elmer run: `meta.json`, `model.json`, `mesh.npz` and `results/case_t*.vtu`. The mesh topology is the split mesh (CTETRA, CHEXA, CPENTA, CTRIM6, CTRIA3).

Variables (Elmer names in parentheses):
* Structural: `u`, `v`, `w` (displacement x,y,z), `disp_mag` (magnitude), `vonmises` (von Mises stress), `sxx`, `syy`, `szz`, `sxy`, `syz`, `sxz` (stress components)
* Thermal: `T` (temperature), `t` (alias for T)

Stresses are element-averaged to nodes (each node gets the mean of its incident elements' von Mises values). The 3D von Mises is computed from the six stress components printed by NASTRAN for solid elements.

=== Convergence

The log is judged with the same statuses as Elmer runs:

* *converged*: `* * * END OF JOB * * *` reached, no `USER FATAL MESSAGE` or `SYSTEM FATAL MESSAGE`, and at least one result variable (displacement, temperature, eigenvalue) was produced.
* *not converged*: NASTRAN exited with a non-zero code but produced some output (rare; usually fatal errors are caught first).
* *failed*: NASTRAN wrote a `USER FATAL MESSAGE` or `SYSTEM FATAL MESSAGE`, did not finish within the time limit (30 min, `ELMERSTUDIO_NASTRAN_TIMEOUT`), or produced no results.

The timeout and the WSL temp-dir copy-back are handled by the NASTRAN runner; the study's Messages report the wall time and any diagnostic.

=== What is refused

Each of these stops *Compute* before any file is written, with the reason:

* physics other than Solid Mechanics and Heat Transfer in Solids, and more than one physics interface in a study step;
* multiphysics couplings;
* eigenfrequency and frequency-domain studies in transient or non-linear modes;
* 2D axisymmetric components;
* geometry that requires curved boundary representation beyond the mesh's quadratic elements (NASTRAN-95 accepts only straight-sided elements);
* Solid Mechanics: volume force with non-constant density, properties that differ between domains in a way NASTRAN cannot map;
* Heat Transfer: Surface-to-Ambient Radiation, convection boundary, temperature-dependent properties;
* a boundary condition on an interior boundary (would need MPC or rigid element);
* a physics interface that does not cover every domain of the component;
* mesh Size nodes on boundaries, edges or points; a Distribution spanning more than one block interval, or two that conflict;
* a study that solves several components with different backends.

=== Limitations

* *3D normal modes (SOL 3) accuracy*: The inverse power method (INV) used for 3D models with coarse tetrahedral meshes yields the first bending frequency within ~30% of Euler-Bernoulli theory. For the 3D cantilever (L=1.0, H=0.05, W=0.01), measured f1 ≈ 51.2 Hz vs. theory 40.8 Hz (25.7% error). This is due to shear locking and mesh coarseness in thin-beam tetrahedral meshes. Refine the mesh or use hexahedral elements for better accuracy. The f2/f1 ratio remains within 15% of theory.
* *von Mises stress at boundaries*: Nodal averaging may slightly underestimate stress at boundary nodes with fewer connected elements. The interior stress field is accurate.

=== Out of scope

Non-linear analysis, transient structural/thermal (SOL 9, HEAT 9), frequency response (SOL 11), buckling (SOL 5), optimization (SOL 200), superelements, fluid-structure interaction, piezoelectric, and parallel DMAP runs. Use Elmer for these, or run the exported deck by hand.
