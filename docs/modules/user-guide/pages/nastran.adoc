= NASTRAN-95 backend
:description: Solving Solid Mechanics and Heat Transfer with NASTRAN-95 instead of ElmerSolver: what is mapped, how accurate it is, what is refused and why.

A study can be solved by *NASTRAN-95*, the public-domain release of NASA's structural analysis program, instead of ElmerSolver. You build the model exactly as for Elmer: geometry, materials, physics features, mesh, study. Only the study's *Solver backend* setting changes. The results come back into the same Results machinery, with the same variable names and SI units as an Elmer solution, so plots, derived values, selections and export work unchanged.

The same model means the same problem: loads, constraints, the 2D plane strain or plane stress setting and the per-unit-depth convention of 2D models are translated so that NASTRAN-95 solves what Elmer would. Anything that cannot be translated faithfully is refused before anything runs, with a sentence saying why. Elmer Studio never falls back to Elmer silently, and never drops a feature it cannot map.

== Choosing the backend

Select the study node and set *Solver backend* (section _Study Settings_) to *NASTRAN-95*. The default is *Elmer*, and models saved before this setting existed open with Elmer.

When the model cannot be solved by NASTRAN-95, *Compute* is unavailable and its tooltip says why ("Unavailable: ..."), and the study node carries an error mark with the same sentence. Reasons that need the geometry or the mesh are reported when you click *Compute*, before anything runs.

NASTRAN-95 is looked up in this order:

. `NASTRAN_WSL_HOME` (Windows): the Linux path of a NASTRAN-95 build inside WSL, the folder that holds `dist/bin/nastran` and `rf/`, for example `/home/<user>/NASTRAN-95`;
. the *NASTRAN-95 installation folder* in menu:File[Preferences...];
. the environment variables `NASTRAN_ROOT`, `NASTRAN_EXE`, `NASTRAN95_ROOT` and `NASTRAN_HOME`;
. common install folders, such as an unpacked release in your Downloads folder, and `nastran` on the `PATH`;
. on Windows, a build found inside WSL.

A folder is accepted when it holds the `nastran` executable (also under `dist/bin/`) and the rigid formats folder `rf/`. Releases for Windows and Linux are published at https://github.com/AltElmer/NASTRAN-95/releases[AltElmer/NASTRAN-95].

With the NASTRAN study selected, menu:Study[Show NASTRAN Input Deck] shows the generated deck without running anything: the Executive Control and Case Control decks and the Bulk Data with all GRID, material, element, SPC and load cards. *Save As...* writes it to a `.bdf` file you can run by hand.

== What is mapped

[cols="1,3",options="header"]
|===
|Model |NASTRAN-95
|*Solid Mechanics*, Stationary |`APP DISP`, `SOL 1` (linear statics), linear elastic material
|*Solid Mechanics*, Eigenfrequency |`APP DISP`, `SOL 3` (normal modes): the lowest _Desired number of eigenfrequencies_ modes by the FEER method, mass normalized, with their mode shapes
|*Heat Transfer in Solids*, Stationary |`APP HEAT`, `SOL 1` (steady conduction), linear isotropic material, fixed temperatures
|2D components |Per unit depth, as in Elmer. Plane strain (the default of the interface) or plane stress, from the interface's 2D approximation setting
|3D components |Solid elements
|Parametric sweeps |One NASTRAN run per parameter value
|===

=== Feature mapping

[cols="2,3",options="header"]
|===
|Studio feature |NASTRAN-95 cards
|Linear Elastic Material (E, ν, ρ) |`MAT1`; in 2D plane strain with E/(1-ν²) and ν/(1-ν), which gives NASTRAN's plane stress membrane the plane strain stiffness
|Heat Transfer in Solids (k, ρ, C~p~) |`MAT4`
|Fixed Constraint |`SPC1` on the boundary's grid points, displacement components 1, 2 (and 3 in 3D)
|Prescribed Displacement |`SPC` with the prescribed value, for each direction that is switched on
|Roller, Symmetry |`SPC1` on the normal component; the boundary must be perpendicular to the x, y or z axis
|Boundary Load: force per unit area, total force, pressure |`FORCE` cards: the load integrated over the boundary into consistent nodal forces of the elements NASTRAN solves; a pressure acts along the inward normal, as in Elmer
|Body Load |`FORCE` cards: the force per unit volume integrated over the selected domains
|Gravity |`GRAV` with the material density; it must act on the whole model
|Temperature |`SPC` with the temperature on the boundary's grid points
|Thermal Insulation, Symmetry (heat), Free |Nothing to write: they are the natural boundary condition
|===

=== Elements

Every mesh node becomes a `GRID` card (grid ID = node number). NASTRAN-95 has no quadratic triangle or tetrahedron that passes the patch test, so the quadratic elements of the Studio mesh are split into linear ones that keep all the nodes:

* a 6-node triangle into 4 `CTRIA3` (with `PSHELL`, unit thickness);
* a 10-node tetrahedron into 8 `CTETRA`;
* linear triangles, quadrilaterals, tetrahedra, hexahedra and prisms map one to one to `CTRIA3`, `CQUAD4`, `CTETRA`, `CHEXA` and `CPENTA`.

Quadratic quadrilaterals, hexahedra and prisms (from mapped or swept meshes) and pyramids are refused: use a free triangular or tetrahedral mesh. In 2D the grid points carry `PS=3456` (a plane membrane), in 3D `PS=456` (solid elements have no rotational stiffness).

NASTRAN-95's own 6-node membrane `CTRIM6` is not used: on coarse free meshes it does not reproduce a uniform stress state, with element stresses off by 30 to 50 percent in pure tension.

=== Accuracy

Linear elements are exact for uniform stress and linear temperature fields and converge more slowly than Elmer's quadratic elements in bending. Measured on the same models solved by both backends:

[cols="3,2,2",options="header"]
|===
|Model |Element size |NASTRAN-95 vs Elmer
|2D bar in tension (plane strain or plane stress) |50 mm |0.1 %
|2D block on rollers in tension |50 mm |1 %
|2D steady conduction, fixed end temperatures |100 mm |2·10^-4^ K
|2D cantilever under pressure, tip deflection |25 mm (2 elements through the 50 mm depth) |10.5 % stiffer
|same |12.5 mm (4 elements) |2.0 % stiffer; peak von Mises stress 7 % lower
|2D cantilever, first three eigenfrequencies |12.5 mm |1.0 % higher; mode shapes identical (correlation 1.000)
|3D cantilever, tip deflection |50 mm (1 element through the depth) |40 % stiffer
|===

For bending, refine the mesh through the thickness: four or more linear elements through the depth in 2D, and more in 3D, where linear tetrahedra are stiffer still.

=== Results

Each solution folder holds the NASTRAN case (`nastran/case.inp`, with `case.out` for a native build), the solver output in `solver.log`, and the same files as an Elmer run: `meta.json`, `model.json`, `mesh.npz` and `results/case_t0001.vtu`. The result mesh is the Studio mesh, so results can be compared node by node with an Elmer solution of the same model.

Variables (Elmer names, so the usual expressions such as `solid.disp` and `solid.mises` work):

* Solid Mechanics: `displacement` (`u`, `v`, `w`), `disp_mag` and `vonmises`. The von Mises stress is the element value averaged at the nodes; in 2D plane strain it includes the out-of-plane stress ν(σ~1~ + σ~2~).
* Eigenfrequency: the eigenfrequencies and, for each mode, its mode shape (`displacement EigenMode1`, ...), selected by the mode in plots as for an Elmer solution. Stresses are not computed for modes.
* Heat Transfer: `temperature` (`T`).

=== Status

* *converged*: `END OF JOB` reached, no `USER FATAL MESSAGE` or `SYSTEM FATAL MESSAGE`, and displacements, temperatures or mode shapes were produced.
* *failed*: a fatal message (it is shown in Messages), a non-zero exit code, no results, or no end within the time limit (30 min, `ELMERSTUDIO_NASTRAN_TIMEOUT` in seconds).

=== What is refused

Each of these stops *Compute* before anything runs, with the reason:

* physics other than Solid Mechanics and Heat Transfer in Solids, more than one physics interface in a study step, and multiphysics couplings;
* study steps other than Stationary and Eigenfrequency (Time Dependent and Frequency Domain have no NASTRAN-95 deck yet);
* 2D axisymmetric components;
* features without a NASTRAN-95 card, for example Heat Flux, Spring Foundation and heat sources;
* a Roller or Symmetry on a boundary that is not perpendicular to a coordinate axis;
* Gravity on part of the model, or with its own density;
* a study step that takes its initial values from another study;
* elements that would leave grid points without stiffness (see <<elements>>).

=== Out of scope

Non-linear analysis, transient analysis (rigid formats 9 and HEAT 9), frequency response, buckling, superelements and DMAP alters. Use Elmer for these, or edit the saved deck and run NASTRAN-95 by hand.
